# Goals — Urban Laundromat

One file per design goal. Use `NN-<slug>.md`; never overwrite an earlier goal. Multiple goals per
project are expected.

- Start from `01-project-brief.md` for the first goal.
- Fill goals only after requirements are confirmed, workflow and review answers are collected,
  scaffolding exists, and all three exact records are persisted.
- Each recorded goal contains mission, visual outcome, scope, deliverables, acceptance, and done.
  The orchestrator manages its lifecycle through `blender-project-goal`; users provide inputs.
- Link `../REQUIREMENTS.md`, `../WORKFLOW.md`, and `../REVIEW.md`; do not duplicate their contents.
- Identify the active goal's actual file path for production and grading. Do not assume
  `01-project-brief.md` remains active beyond initial bootstrap.
- These are design goals, not coding plans. Do not add `PLAN/` records.
- Before reporting complete, update README, `REQUIREMENTS.md`, `WORKFLOW.md`, `REVIEW.md`,
  `DECISIONS.md`, and `ASSETS.md`. Require a saved inspected review render and final applicable
  `PASS` when grading is enabled, with no genuine unresolved blocker or major finding.
